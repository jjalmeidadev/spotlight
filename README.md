# Spotlight

## Grupo 04 - Dora

## 📝 Descrição

O Portal Aventura reúne um dos maiores catálogos de espetáculos do Brasil: musicais, ballet, teatro infantil e produções premiadas. Mas por muito tempo, quem entrava no portal via apenas o que já havia buscado. Um visitante que chegava para ver "Mamma Mia!" saía sem saber que "Elis, a musical" existia.
Cada sessão encerrava com oportunidades de descoberta desperdiçadas.

O **Spotlight** nasceu para mudar isso.

Um sistema de recomendação inteligente integrado ao Portal Aventura que, a partir das preferências declaradas pelo usuário e do seu comportamento de navegação, sugere espetáculos relevantes no momento certo da jornada, transformando uma visita pontual em uma experiência de descoberta cultural contínua.

O resultado é uma jornada mais conectada: o público descobre produções que combinam com seu gosto, a Aventura amplia seu alcance dentro do próprio portal, e cada acesso se torna uma nova oportunidade de aproximar pessoas
da cultura.


## A solução

O Spotlight analisa as preferências e interações de cada usuário para gerar
recomendações personalizadas de espetáculos, conteúdos e experiências
culturais. A plataforma estimula a navegação dentro do portal, aumenta o
tempo de permanência e cria uma jornada mais conectada entre as produções
da Aventura — levando o público certo ao espetáculo certo.

## ⚙️ Instalação e execução

### Pré-requisitos

O ambiente usado para validar estes comandos foi:

- Node.js `v24.11.1` e npm `11.6.2`
- .NET SDK com suporte a `net9.0` (validado com SDK `10.0.202`)
- Docker `29.2.1` com Docker Compose `v5.1.0`

Em Windows/PowerShell, caso a política de execução bloqueie os shims `npm` ou `npx`, use `npm.cmd` e `npx.cmd`.

### Configuração inicial

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm.cmd ci
dotnet restore .\src\backend\Spotlight.sln
```

Depois de copiar o `.env`, preencha os valores reais antes de executar fluxos integrados. As variáveis mais importantes são `DATABASE_CONNECTION_STRING`, `SUPABASE_JWT_SECRET`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`, `EXPO_PUBLIC_API_BASE_URL`, `MONGODB_CONNECTION_STRING`, `MONGODB_DATABASE` e `MONGODB_TELEMETRY_COLLECTION`.

### Execução local sem Docker

Frontend Expo:

```powershell
npm.cmd run web
```

Backend completo em terminais separados:

```powershell
dotnet run --project .\src\backend\api-gateway\Spotlight.Gateway.csproj
dotnet run --project .\src\backend\services\catalog\Spotlight.Catalog.csproj
dotnet run --project .\src\backend\services\user\Spotlight.User.csproj
dotnet run --project .\src\backend\services\recommendation\Spotlight.Recommendation.csproj
dotnet run --project .\src\backend\services\geolocation\Spotlight.Geolocation.csproj
```

Portas padrão:

- Gateway: `http://localhost:5000`
- Catálogo: `http://localhost:5001`
- Usuário: `http://localhost:5002`
- Recomendação: `http://localhost:5003`
- Geolocalização: `http://localhost:5004`

### Execução com Docker

Desenvolvimento full-stack:

```powershell
docker compose -f docker-compose.dev.yml up --build
```

Produção full-stack:

```powershell
docker compose -f docker-compose.prod.yml up --build
```

Somente serviços backend de domínio, sem gateway e sem frontend, usando o Compose legado/compacto:

```powershell
docker compose up --build
```

### Validação

Comandos executados e validados nesta atualização:

```powershell
npm.cmd ci
npm.cmd run build:web
dotnet restore .\src\backend\Spotlight.sln
dotnet test .\src\backend\Spotlight.sln --no-restore
docker compose -f docker-compose.dev.yml config --quiet
docker compose -f docker-compose.prod.yml config --quiet
```
